# HyScribe

Rust drop-in replacement for WordPress. The MVP is met and the first release is being prepared; see [README.md](README.md) and `docs/`.

## Read first

1. [GOALS.md](GOALS.md): what we are building and the success criteria
2. [docs/SECURITY_MODEL.md](docs/SECURITY_MODEL.md): the top priority and its rules
3. [PROGRESS.md](PROGRESS.md): current phase and next actions
4. [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md): the contract every change must respect

## Commands

- Tests: `cargo test --workspace` (build the Theme Test Data fixture once with `reference/theme-test-data/build.sh`, then start the fixture databases: `reference/default-install/db.sh up`, which also exposes the database socket in `/tmp/hyscribe-db-<port>/` and creates `wordpress_saves`, a scratch database writing tests reload; after any PHP page views, take `php.sh` down and start from a fresh `db.sh up`, as CI does, since PHP writes a `wp_navigation` post the fixture lacks)
- Coverage gate: `cargo llvm-cov --workspace --ignore-filename-regex '/tests/' --fail-under-lines 100 --fail-under-regions 100`
- Mutation testing: `cargo mutants --workspace`
- Supply chain: `cargo deny check`, `cargo vet` (a new dependency needs an audit or an imported one; exemptions in `supply-chain/config.toml` only shrink)
- Extension host: `hyscribe-ext`'s tests build the test extension (on `hyscribe-sdk`) with `crates/hyscribe-ext/guest/build.sh` (`build.sh theme` for the test theme of ADR 0023; needs `rustup target add wasm32-wasip2`); mutants of `hyscribe-sdk` take `--test-package hyscribe-ext`; its cost measurement: `cargo test --release -p hyscribe-ext --test cost -- --ignored --nocapture`
- Switch-back suite (MVP 8.5, slow, a release gate): `reference/switch-back/run.sh [log folder]` (takes `HYSCRIBE_PHP_CONTAINER` and `HYSCRIBE_PHP_PORT` for a private PHP container; `RESTART` lines in `actions.list` restart HyScribe with other `.env` keys) (a fresh `db.sh up`; HyScribe's binary writes `actions.list` over HTTP, then `php.sh up` on the same database runs `check.php` and `pages.list` under `WP_DEBUG`; resets the database after; `HYSCRIBE_ORACLE_LOCK` makes the PHP part wait for the shared oracle); `HYSCRIBE_SWITCH_BACK_FIXTURE=ttd` runs its REST subset over `wordpress_ttd` (`actions-ttd.list`, `pages-ttd.list`); `SLEEP`, `CRON`, `SQL` and `INSTALL` (`hyscribe plugin install` of the test extension, packaged by the test) method lines and `upload:<part>:<corpus file>:<fields>` bodies are in `actions.list`, and `run.sh` gives PHP the plugin the test extension stands in for (`reference/plugins/hyscribe-test`); `HYSCRIBE_PHP_UPLOADS` makes `php.sh` serve a given uploads folder
- Screenshot comparison (GOALS S8, slow): `reference/screenshots/golden.sh [report folder]` (a headless Chromium in Docker, the image pinned by digest in `reference/screenshots/Dockerfile`, photographs the screens of `screens.list` as each role from PHP and then from HyScribe's release binary (`HYSCRIBE_BIN`, default `target/release/hyscribe`) over the same fresh fixture database, both answering as `http://wp.test` on the slot's network, and compares them pixel by pixel; a channel more than 16 of 255 apart counts as different, a screen matches at the same size with at most 0.01 percent of pixels different; the report folder, `target/screenshots` by default, gets `report.tsv`, `report.html` and a `diff-<screen>.png` for each difference; exit 1 when one differs; takes the `db.sh` variables and `HYSCRIBE_ORACLE_LOCK`; `HYSCRIBE_SHOTS_KEEP_PHP=1` reuses the PHP pictures of the last run; needs network once for the images; the expected differences are listed in `reference/screenshots/expected.list`)
- Plugins from the command line: `hyscribe plugin install [--unsigned] <file>` (ADR 0024: `<file>.minisig` must verify against the registry key list kept in `registry/` or a key in `EXTENSION_TRUSTED_KEYS`; tests sign with `hyscribe_testkit::minisign` keys and pass test roots, never configuration), `hyscribe plugin install <name>[@<version>] [--downgrade] [--allow-new-grants] [--replace-local]` and `hyscribe plugin update --check | <id>... | --all` (from the hosted registry at `EXTENSION_REGISTRY`; the service checks it every 12 hours with `EXTENSION_UPDATE_CHECK=on` and `HTTP_OUTBOUND=on`; tests serve a registry over HTTPS with `hyscribe_testkit::registry::Served`, never a real network), `hyscribe plugin delete <id>` (removes `plugins/<id>/` and its kept packages; refuses an active plugin, writes nothing to the database)

## Working rules

- **Security is the first priority** (ADR 0006, docs/SECURITY_MODEL.md). When security conflicts with anything else, security wins. No `unsafe` outside the reviewed allowlist, no string-built SQL, no execution of files from disk, every parser gets a fuzz target, ports never reproduce known vulnerabilities
- Work on the `development` branch; `main` only receives reviewed merges
- Never change WordPress core table schemas, and never write data PHP WordPress would not write (ADR 0003)
- PHP WordPress is the test oracle: behaviour claims need a differential or golden test
- **Full test coverage** (ADR 0007, docs/TESTING.md): every change ships with tests in the same commit; 100% line and region coverage, coverage never decreases, no surviving mutants in changed code; a bug fix starts with a failing test; exclusions only with a reason in `coverage-exclusions.md`
- Architectural choices get an ADR in `docs/adr/`
- License is AGPL-3.0-or-later: every source file starts with `// SPDX-License-Identifier: AGPL-3.0-or-later` (the extension SDK crates, when they exist: `Apache-2.0 OR MIT`); never port GPLv2-only or non-GPL code (ADR 0004)
- Supported WordPress range starts at 7.0
- Deployment is a single self-contained binary from a `tar.gz`, running itself as a service (ADR 0005). Never add a runtime dependency other than the database; Docker is optional only
- Everything an installation writes stays inside the `hyscribe/` folder in plainly named subfolders (`plugins/<slug>`, `themes/<slug>`, `uploads/`, `logs/` and so on, see docs/DEPLOYMENT.md); public URLs keep their `/wp-content/...` paths
- **Keep the code lean.** Every round of work ends with a review for dead, unused or duplicated code (an independent review reads the workspace), and the findings are pruned before moving on. No speculative helpers, unused dependencies or leftover placeholders
- After meaningful work, update `PROGRESS.md` (status, checklist, next actions) and add a dated entry to `HISTORY.md` for decisions or milestone changes
- The client address always comes from `comment_post::client_ip` (`TRUSTED_PROXIES`); never read `X-Forwarded-For` directly
- hs-admin prints screen URLs without `.php` (ADR 0008 amendment): build links with `admin_url()` or `menu::link`; a page made outside `admin_page` goes through `hyscribe_admin::menu::clean_links`
- The dashboard is hs-admin and emulates `wp-admin` as closely as possible (ADR 0008, docs/ADMIN.md): same screens, file names, markup and CSS classes under `/hs-admin/`.
- The first test target for every layer is the default WordPress install fixture (docs/TESTING.md)
- Every subsystem exposes WordPress's filter and action points under their WordPress names and argument order, so plugins convert by attaching to the same hooks; plain internal calls until the extension runtime (M6); a hook never skips a check and runs in bounded time (docs/EXTENSIONS.md)
